# 开源硬件案例与自动化工具研究

研究日期：2026-11-21（Asia/Shanghai）。目标：嘉立创 EDA 专业版、四层 MCU 控制板。这里只记录实际读取的公开材料；来源、时间、文件 SHA-256 及许可见 [sources.json](sources.json)。完整网页/工程文本保留在本地 `snapshots/`，不随仓库发布。未安装、运行或联调这里列出的第三方工具。

## 1. 已读取的硬件，不把两层示例说成四层

### Raspberry Pi RP2040 Minimal Design Example R3

官方设计包：<https://datasheets.raspberrypi.com/rp2040/Minimal-KiCAD.zip>。实际下载约 814 KB 的压缩包，仅解包原理图、PCB、工程配置和许可证；没有解包或查看附带 PDF、BOM。该包的当前源文件具有以下可复核内容：

- PCB 标题 `RP2040 Minimal Design Example`，版本 R3，日期 `2026-07-03`。
- 生成器 KiCad `10.0`，PCB 文件版本 `20260206`；板厚 `1 mm`。
- 铜层只有 `F.Cu` 与 `B.Cu`。**这是两层工程**，不是四层案例。
- 对 PCB 全文件做 S-expression 结构解析，得到 34 个 footprint、313 个 segment、28 个 via。此处计数是结构检查，不是 DRC 结论。
- U3 是 RP2040；焊盘 46 / 47 的引脚功能分别为 `USB_DM` / `USB_DP`。它们接到 `Net-(U3-USB_DM)` / `Net-(U3-USB_DP)`，不应仅按网络名称里有没有 `D+`/`D-` 来识别差分对。
- U2 是 W25Q128JVSIQ。焊盘 1→`/QSPI_SS`、2→`/QSPI_SD1`、3→`/QSPI_SD2`、5→`/QSPI_SD0`、6→`/QSPI_SCLK`、7→`/QSPI_SD3`；4→GND、8→+3V3。
- U3 的焊盘号 57 有多个物理实现，同接 GND。一个逻辑引脚可能对应多个物理焊盘，不能要求每个“位号+焊盘号”只出现一次。

依据：[case-rp2040-pcb]、[case-rp2040-schematic]、[case-rp2040-project]。提取详情保留 `snapshots/hardware-extract-rp2040.json`；可用 [inspect_hardware.py](inspect_hardware.py) 重算。

包内许可证为 MIT，`Copyright (c) 2026 Raspberry Pi Ltd`，并声明参考设计和尺寸不作保证，实际封装/尺寸需对照厂商资料与实物核验。[case-rp2040-license]

**可复用方向：**在用户未确定具体 MCU 时，这是有来源、较小且包含 USB/外部 Flash/调试接口的候选基准。可从该原理图建立自有嘉立创专业版工程，单独设计四层方案，然后比较电气连接与约束；不能宣称原有两层布局或规则已经验证了新四层板。新工程应保留来源与 MIT 声明。若用户选择其他 MCU，以其具体数据手册/封装/设计指南为准。

### OLIMEX ESP32-PoE B1

官方仓库：<https://github.com/OLIMEX/ESP32-POE>。本次取得 B1 对应旧版 KiCad 原理图及 PCB，来源 Git blob 已记录，仓库树 SHA 为 `deb38a377d50eadb04ddc7118a17a5ae58b1ee53`。

实际 PCB 结构为两铜层、1.6 mm 厚、123 个 module、133 条 net 声明（包括编号 0 的空网）、2429 个 segment、176 个 via。可找到 ESP-WROOM-32（U9）、LAN8710A（U4）、+5V、+3V3、GND、UART、RMII 等网络。

它对插件有三项很具体的启发：

1. U4 在 `B.Cu`，导入导出时必须区分器件位置/旋转/镜像，不能以顶视图坐标直接替代底面器件变换。
2. U4 多个编号 33 的物理焊盘同接 GND。散热焊盘、焊盘内孔、重复电气焊盘需要保留“逻辑引脚→物理焊盘集合”，不能简单去重。
3. `USB-UART1` 含无编号 NPTH 和同号外壳焊盘；NPTH 机械孔不能被分配电气网络，外壳焊盘应保持原网络属性，不能默认全部等于 GND。

依据：[case-olimex-b1-pcb]；原理图已取得，但尚无全板原理图连通性解析器，因此不声称完成原理图/PCB 电气一致性验证。[case-olimex-b1-sch]

官方 README 分开规定：硬件 Apache-2.0、软件 GPL3、文档 CC BY-SA-3.0；根 LICENSE 只证明 Apache-2.0 文本，不能据此给仓库所有内容统一贴 Apache 标签。[case-olimex-readme]、[case-olimex-license] 本项目研究其映射边界，不直接拷贝 PoE 电源或整板布局。复杂 PoE、RF 与隔离相关设计不适合作为第一块简化 MCU 验证板的默认功能。

## 2. 四层 MCU 设计的厂商证据

已实际读取 Espressif ESP32-S3 官方 `PCB Layout Design` HTML。它推荐四层，并明确第二层保持完整 GND、第三层电源及少量信号时仍要保证 RF/晶振下方参考地、底层少量走线；还允许在条件满足时使用两层。这说明“给板子设成四层”与“参考平面/回流设计正确”是两件事。[case-esp32-s3-layout]

可转为带适用条件的规则：

- ESP32-S3 USB 差分阻抗目标为 90 Ω±10%；尽量减少换层，必要换层处加入一对接地回流过孔，保持下方连续参考面。实际线宽/间距必须结合制造商指定叠层求解，不能从目标阻抗直接猜一个固定 mil 数。
- 芯片裸片/裸芯片外围设计与成品模组底板设计分开处理。模组天线净空、板边位置和外壳影响，与主板普通数字地规则不同。
- RF 走线目标 50 Ω，避免分支/换层；官方还列出晶振、RF、Flash/PSRAM、去耦及干扰处理。部分做法与特定封装/匹配结构有关，不能提炼成所有 MCU 的硬规则。
- USB、RF、晶振与电源线路分别生成约束与检查项；不能因为全板 DRC 清零，就宣称阻抗、射频或供电完整性通过。

本次未取得或验证四层 MCU 的实际嘉立创工程，也未做 SI/PI、阻抗仿真或实板测试。以上是厂商文档规则，工程效果仍需相应证据。

### 多层实物工程补充：HackRF One（4 铜层，MCU + RF）

在用户指定后追加查找并实际读取 Great Scott Gadgets 官方 HackRF One PCB 与 MCU 层次原理图。对应官方 README 明确写为四层、1.6 mm，层序为 front `C1F`、内层 `C2`、内层 `C3`、back `C4B`。PCB S-expression 中相应铜层为 `F.Cu`、`In1.Cu`、`In2.Cu`、`B.Cu`。源工程版本 `20211014`，板厚记录 `1.6116 mm`。

2026-11-22 又从同一官方 Git 树下载并以 Git blob SHA-1 校验 root、baseband、frontend 三张 KiCad 原理图、工程设置、缓存/自定义符号和库表。工程完整性检查已扩展到可导入包；这一步仅确认文件来自记录的 blob，尚未证明嘉立创能完整导入或全层次网表映射正确。

`snapshots/` 中 PCB 顶层结构解析出 437 个 footprint、3817 条 segment、498 个 via、380 个 net 定义、9 个 zone。segment 分布为 F.Cu 2848、B.Cu 925、In1.Cu 29、In2.Cu 15。区域包括 In1.Cu 的 GND，以及 In2.Cu 的 VCC、VAA。这是真正含内部铜层走线和网络铜区的多层工程证据，不仅是项目说明文字。[case-hackrf-one-pcb]

README 还列出该板当时的叠层：外层铜 0.035 mm、内层铜 0.0152 mm；介质 0.2104/1.065/0.2104 mm，7628 prepreg，Er=4.6±0.1。README 记载其 50 Ω±5% 设计与 11.55 mil microstrip。它可以验证多层工程数据结构能否完整解析（层号/层名映射、跨层对象、分层 net/zone、工程版本/栈厚）并展示这些值如何依赖一份具体叠层。[case-hackrf-one-readme]

这是宽带 SDR 射频设备，含 LPC4320 MCU，不是初始 MCU 控制板的布局范本，也不代表这些古早制造备注适用于当前嘉立创订单。只把它用作**多层数据结构解析与层序映射回归用例**；器件布局/射频设计另按相应芯片和天线要求复核。其 README、PCB、MCU 原理图与许可证使用各自的 Git blob SHA-256/抓取记录固定溯源。[case-hackrf-one-mcu-sch] 仓库许可证为 CERN-OHL-P v2。[case-hackrf-one-license]

### 层数误判负例：Adafruit Feather STM32F405 Express

实际读取 Adafruit Eagle `.brd` XML，而非只看网页产品介绍。此文件的 `layerSetup` 为 `(1*16)`；板文件虽声明 Eagle 的 1 到 16 层编号范围，实际走线 wire 仅分布于 1 与 16 层各 588、227 条（加 1 个双面各一的铜区）；当前板实际是**两层**。README 和 PCB 确实包含 STM32F405R、USB-C D+/D− 和实际功能外设。[case-adafruit-f405-pcb]

这提醒插件不能用“格式支持 16 层”或图形图层表中出现内层名称来推断实际叠层。每个 EDA 格式都应同时解析：板文件当前启用的层序/叠层定义、实际铜图元所在层、必要时板层配置；若不同来源互相冲突，就标记不确定并停止自动映射。Adafruit 许可证为 CC BY-SA 3.0，复用工程内容应保留署名及相同方式共享条件。[case-adafruit-f405-license]

## 3. 工具选择与嘉立创适配界限

| 工具 | 实际读取证据 | 能为本项目提供什么 | 目前不能承诺什么 | 许可 |
|---|---|---|---|---|
| 嘉立创 EDA 专业版 | 由 EDA 研究分支单独核验 | 应作为主编辑器与最终原生 DRC/导出环境 | 本分支未连接用户专业版实例 | 见 EDA 研究 |
| KiCad CLI | 官方 9.0 CLI 手册 | 格式转换研究的旁路、可机器读取的 DRC/ERC/制造文件生成模式 | 不是嘉立创专业版 DRC；未安装/运行；9.0 文档不能证明可读取 KiCad 10 文件 | 文档 GPL v3+ 或 CC BY 3.0+ |
| Freerouting | 官方 README、LICENSE | 本地候选布线引擎、DSN→SES、CLI 与 MCP 参考 | 未证明专业版的 DSN/SES 无损往返，不能替代布局/约束/SI/PI | GPL-3.0，服务条款独立 |
| tscircuit | 官方 README、LICENSE | 把元件/网络/布局写成代码的产品参考，制造文件导出模式 | 未证明能双向编辑嘉立创专业版原生工程 | MIT |

KiCad 的 `pcb drc` 支持 JSON、`--schematic-parity` 和 `--exit-code-violations`。最后一个选项启用时，文档规定无违规返回 0，有违规返回 5；不加它时，不能凭进程成功退出就证明板子合格。`sch erc`、Gerber、Excellon 钻孔等也有 CLI 命令。这是一种可借鉴的验收接口设计，仍需嘉立创自己的规则结果作为主证据。[case-kicad-cli-9]

Freerouting 官方 README 明确输入 `.dsn`、输出 `.ses`，`-de`/`-do` 指定输入输出。读取时的 README 已列 MCP 与本地执行模式。因而“有 MCP”本身不是本项目的差异，差异应是**可靠理解原理图/约束，控制专业版，保留设计意图并验证结果**。若研究使用 Freerouting，先做包含板框/禁布区/层/网络类/锁定线路/过孔的往返测试，再考虑接入；自动布线结果需要原生 DRC 及约束检查。[case-freerouting-readme]、[case-freerouting-license]

tscircuit 以 React/TypeScript 表达元件、pin 与 net；README 给出预览及 Gerber、BOM、坐标导出能力。这适合参考“结构化电路中间表示”和可重复生成的体验，但 Gerber 是制造输出，不足以证明专业版中元件、规则与网络均可编辑、无损保留。[case-tscircuit-readme]、[case-tscircuit-license]

## 4. 第一阶段应具备的测试，而非口头“会画板”

下面是建议验收用例；本次没有执行这些 EDA 行为测试。

| 用例 | 输入/触发 | 期望证据 |
|---|---|---|
| 小型 MCU 端到端 | 用户确认的原理图、板框、叠层、封装与电源要求 | 专业版可编辑工程；网络/引脚映射差异为空；原生 DRC 结果可追溯；导出制造资料 |
| 重复物理焊盘 | RP2040 U3 的多个 57/GND，或 OLIMEX U4 的多个 33/GND | 所有物理焊盘保留，网络一致，无错误去重/短接 |
| 机械孔与外壳 | 无编号 NPTH、同号屏蔽壳焊盘 | 机械孔保持机械属性；屏蔽焊盘保留网络，不擅自归地 |
| 引脚换接 | 在测试副本中交换 QSPI_SD0/SD1 或 USB D+/D− | 原理图到 PCB 一致性检查能报差异，并指出器件/焊盘/网络；不能只做网名数量比较 |
| 底面器件变换 | 把测试器件放到底层并改变旋转 | 保存/重开后坐标、角度、层、镜像和引脚方向一致 |
| 四层参考面 | USB 下方故意放参考面割缝，或在关键处换层且没有回流过孔 | 规则审查指出连续性/回流问题；注明这类检查是否为几何启发式；不冒充 SI 仿真 |
| 原理图增量 | 已布线工程增加/修改一个元件或网络 | 通过专业版更新机制仅改变必要对象，保留锁定器件/线路与已有设计意图 |
| 叠层变更 | 修改板厚、介质厚度或铜厚 | 原阻抗结论失效并重算/重新确认，不沿用旧线宽结论 |
| 工具故障 | 缺版本、超时、API 返回空、DRC 未实际运行 | 状态为失败/未验证；不得返回“设计通过” |
| 输出复核 | Gerber、钻孔、BOM、坐标导出 | 板框闭合、层序/数量、PTH/NPTH、原点/单位/底面角度、器件数量一致；专业版重新打开设计不丢对象 |
| 多层源格式解析 | HackRF KiCad 20211014 四铜层文件，C1F/C2/C3/C4B 映射 | 解析为 F.Cu/In1.Cu/In2.Cu/B.Cu，统计实际内层 segments/zones 与层名/Net 一致；不能将源板上的堆叠厚度默认为订单栈叠 |
| Eagle 实际层数 | Adafruit STM32F405 `.brd`，`layerSetup=(1*16)` | 识别为仅 1/16 层实际铜走线的两层板，证明不能将 16 这个 Eagle 层范围误读成 16 层制造叠层 |

比较指标应至少分别记录：引脚级网络一致性、未连线/短路数量、DRC 违规与已批准豁免、关键约束覆盖率、证据来源、人工返工量。线长/过孔数量属于质量指标，不足以替代电气和制造约束。高质量通过不能仅由“线都连上了”决定。

## 5. 本阶段留下的问题

1. 用户尚未指定 MCU 型号、封装、原理图与具体专业版版本；RP2040 只是候选参考，不能替用户确定产品电路。
2. 四层实际叠层、阻抗及制造能力以计划订单为准；不从开源板反推当前嘉立创可制造边界。
3. 两个 MCU 控制板参考（RP2040 与 OLIMEX ESP32-PoE）是两层；HackRF 是已核实的四层 MCU+RF 工程，但只适合作为多层结构解析/层序回归，不应拿来直接替代四层 MCU 控制板方案。任何从两层改成四层的设计都要明确“复用已核对原理图、重新设计层叠和布局”，并补充专业版原生工程及完整验证证据。
4. 源格式版本必须绑定。本次官方 RP2040 示例已经是 KiCad 10；读到 KiCad 9 CLI 手册不能推出本机有兼容工具。
5. 所有第三方内容的完整快照仅本地研究保存；远程仓库保留原创总结、短证据、摘要与 SHA-256。实际将源设计/代码纳入插件时再按明确的许可证保留声明。
