# 单位、文档身份与几何语义

本页综合 [专业版 API 与工作流研究](../../research/eda/findings.md) 和 [真实 PCB 案例](../../research/cases/findings.md)。这是适配器实现前必须固定的契约，尚无实际 EDA 往返测试。

## 所有坐标携带单位

官方 CLI 单位表明确 SCH=10mil、PCB=mil。不要把以 mm 为内部规范的数值直接传给 API；每个入口核对该版本文档的单位，转换后再读回验证。统一换算：`1 mil = 0.0254 mm`，`1 inch = 25.4 mm`。API 角度逆时针为正；SCH 文件 rotation 与 API 的关系为 `(360 - API角度) % 360`，PCB 文件 angle 同向。仍须核对目标格式版本和接口，不把不同层面的数值直接混用。

原点至少区分文档原点、机械基准、元件局部原点、BOM/CPL 输出原点。输出文件采用哪一坐标系必须记录；Gerber/钻孔错位首先检查输出/解析单位、精度和原点，不能直接移动孔来修补显示。

## 一条几何记录须指向具体工程

文档 UUID、Board、原理图/PCB 关联、会话/窗口标识和基线版本共同确定目标。最后激活窗口或最近打开文件不能替代身份确认。读取后若用户或其他工具修改了文档，原计划的基线可能失效，应重新比较后再继续相关批次。

对象保留稳定 ID；位号可变，不能只靠位号定位旧对象。层 ID、启用状态、铜层/非铜层、信号/内电层分别读取，不从一个整数推断层的制造含义。

## 引脚与焊盘不是一一对应的列表

实际 RP2040 与 OLIMEX 工程都有同号多个物理焊盘。中间模型应保留逻辑引脚到焊盘集合及每个物理实例，机械孔、无网焊盘、散热/屏蔽连接独立表示。不能按列表顺序配对，不能按“位号+编号唯一”删除重复焊盘，也不能把无网络/NC/机械属性全部归入 GND。

顶底面器件位置、旋转和镜像应通过焊盘坐标/引脚方向验证。只比较元件中心位置可能漏掉焊盘翻转。几何相交、同网络名称、铜区显示颜色都不是连通性证明；负片内电层还具有不同的去铜语义。

## 往返测试

用含底面器件、重复散热焊盘、NPTH、不同单位和四铜层的测试副本，读取→变换/写入→保存→重开→重新读取；比较对象数量、ID、网络、层、焊盘位置/朝向和机械尺寸。在没有这种证据前，只声称“字段已读取”，不声称“格式兼容/无损转换”。
