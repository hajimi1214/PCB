# 第一块验证板计划

用户已选：嘉立创 EDA 专业版、4 层 MCU 控制板。已收到可读 `.epro2` 工程并完成离线结构解析。之后经 Windows-MCP UI 打开该在线工程，PCB MCP读取主控板原生网表和ratline。原生网表156器件、512个pad/net映射、104个已分配网络与离线归档多重集完全一致，四个启用铜层也一致；native ratline为0。因此嘉立创EDA原生连通引擎报告该PCB所有网络已布线完成。缓存DRC为notChecked。测试副本路由停在1%后取消并清理。制造/电气验收仍需运行DRC和专项检查。

## 案例与真实工程分开

本轮研究到的开源 PCB 必须按真实层数和版本登记，不能为了符合“四层”目标而改口。两层 MCU 工程可用于验证解析、网络/焊盘映射、封装、元件面与设计变更；它的原理图可作为重新设计四层方案的候选，但新设计需要独立叠层与验证。具体事实见 [硬件研究](../../research/cases/findings.md)。

## 最小试验顺序

1. 根据 [输入表](../../templates/board-intake.md) 固定工程副本、型号、机械、电源与接口要求。
2. 在实际 EDA 中只读能力探测，导出原理图连接和 PCB 元件/焊盘/网络，建立基线；未识别接口显式不支持。
3. 原理图更新 PCB，核对器件和连接差异，测试添加/删除/换封装/改网，尤其检查保留下来的旧走线。
4. 选择实际工厂四层叠层，建立约束；先布局一个可清楚核查的功能块，保存与恢复测试副本。
5. 完成 MCU/供电/接口布局和关键网，再进行一般布线与铜区；每阶段有写后读取和检查证据。
6. 完成 [验收](../concepts/verification.md)，输出制造包，保留首板复核与测量记录。

## 用故障测试能力边界

需要覆盖：不支持/过旧的 API、非 PCB 当前文档、过期 DRC、未完成异步任务、仅一半布局命令成功、网络被外部修改、重复焊盘编号、底面器件、缺少封装、层 ID 变化与单位误读。收到错误时不得继续盲写，也不得把空结果当成无问题。

最终性能以真实板能否逐项验收判断。研究数量、文档数量和路由器完成率都不是替代指标。
